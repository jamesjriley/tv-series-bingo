<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| working-tree → git index | User-authored router fix crosses into version-controlled record |
| logger output → stdout/log file | New `logger.warning` and `logger.exception` may surface user-supplied source_name and game_id in logs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | logger.warning logs body.source_name | accept | source_name comes from user-supplied input that the user themselves typed; it's the show name they chose to play. Already validated in models.py (1-200 chars). Not sensitive. |
| T-03-02 | Information Disclosure | logger.exception captures traceback automatically | accept | Tracebacks may include code paths and parameter names but no secrets — neither game_id nor source_name are credentials. ANTHROPIC_API_KEY would only appear in the traceback if the moment_generator's exception happened to include it in its message; the existing diff already truncates with `str(e)[:200]` for the HTTPException response. Acceptable risk for v1 family-only deployment per CLAUDE.md. |
| T-03-03 | Tampering | wrong commit type prefix (`feat:` instead of `fix:`) leaks into history | mitigate | D-14 locks the subject verbatim. PATTERNS.md commit 3 closing note explains why `fix:` is correct (buggy behavior being repaired). Acceptance criterion verifies exact subject string match. |
| T-03-04 | Denial of Service | new fallback path always succeeds even with garbage YouTube URLs | accept | Previous behavior was strictly worse (deleted the game on any transcript failure). New behavior degrades gracefully to name-based generation, which is the validated existing capability per PROJECT.md. Net win for availability. |
</threat_model>
