## Decisions Made

- **Honour the plan's atomic-commit block over per-task splitting.** The plan staging block lists all five files in a single `git add` invocation followed by a single `feat(pwa)` commit. Wave 1 used the same pattern. Splitting Task 1 into a separate commit would have broken the build between commits (Task 1's `vite.config.ts` references `virtual:pwa-register` indirectly via the plugin, but `main.tsx` doesn't yet import it — partial-state commits are fine, but the commit-per-feature precedent is cleaner).
- **Use `onRegisteredSW` (preferred) over `onRegistered` (deprecated).** Both exist in the type definition; `onRegistered` is marked `@deprecated Use onRegisteredSW instead`. Picked the non-deprecated callback so future updates don't generate warnings.
- **Skip the React hook (useRegisterSW) variant.** Plan and RESEARCH explicitly recommend Option 1 (direct registerSW call) for v1 because there is no in-app "new version available" UI to drive — `autoUpdate` handles the swap silently. The hook would only earn its keep alongside that UI, which D-11 defers to v2.
- **Confirm `/ws` is absent from runtimeCaching, present in server.proxy.** WebSocket upgrade requests bypass the SW at the protocol level (W3C spec, not configurable). Adding a `/ws` runtimeCaching entry would be inert but misleading; its absence is the correct configuration. The dev-server `server.proxy` block (with `ws: true`) is unrelated to the SW and is preserved unchanged for `npm run dev` flow.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] RESEARCH/Plan callback names don't match vite-plugin-pwa's RegisterSWOptions API**
- **Found during:** Task 2 first build attempt (`npm run build` → tsc errors)
- **Issue:** Plan and RESEARCH.md specify `onRegistrationSuccess` and `onRegistrationError` as the registerSW callback names. The actual interface in `vite-plugin-pwa@1.3.0` (verified at `frontend/node_modules/vite-plugin-pwa/types/index.d.ts:RegisterSWOptions`) exposes `onRegistered`, `onRegisteredSW`, and `onRegisterError`. Build failed with three TS errors: `TS2353: 'onRegistrationSuccess' does not exist in type 'RegisterSWOptions'` plus two implicit-any param errors.
- **Fix:** Renamed `onRegistrationSuccess` → `onRegisteredSW` (preferred over deprecated `onRegistered`; takes `(swScriptUrl, registration)` instead of just `(registration)`) and `onRegistrationError` → `onRegisterError`. Both callbacks now log the same diagnostic information; the SW URL is included for free in the success path.
- **Files modified:** `frontend/src/main.tsx`
- **Verification:** Second `npm run build` exits 0; PWA v1.3.0 reports `precache 8 entries (231.47 KiB)`; `dist/sw.js` and `dist/manifest.webmanifest` both generated.
- **Committed in:** `835ff4c` (single atomic commit per D-13)
