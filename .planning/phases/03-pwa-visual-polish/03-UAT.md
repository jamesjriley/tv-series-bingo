## Tests

### 1. Install app prompt in Chromium
expected: Build the frontend (`cd frontend && npm run build && npm run preview`) or use the running dev server, then load the app in Chromium (Chrome/Edge/Brave). Within ~30s of loading, an "Install app" icon appears in the address bar. Clicking it offers to install TV Bingo. After install, the app launches in a standalone window with no browser chrome.
result: skipped
reason: "Deferred to kainga-core production deployment. Pippa uses Firefox on desktop (Mozilla doesn't support PWA install on desktop Firefox). Newly-installed Chromium hit HTTPS-First Mode auto-upgrade against `http://localhost:4173` (ERR_SSL_PROTOCOL_ERROR) and we deferred rather than chase HSTS state. Real users (Mum, Gordie, Pippa) are all Android — Android Chrome supports install natively, but PWA install requires HTTPS, which only exists once deployed via Caddy on kainga-core. The right environment to verify this in is production, not dev."
why_human: Chromium installability is a UI behaviour driven by Chromium's internal heuristics; cannot be tested by grep or curl. Primary APP-03 acceptance criterion.

### 2. Service worker activated
expected: With the app loaded, open DevTools → Application → Service Workers. The panel lists `sw.js` with status "activated and running". Application → Manifest section shows the manifest with three icons rendered, no red warnings.
result: skipped
reason: "Deferred along with Test 1 — same Chromium DevTools dependency, same deployment timing. Indirect evidence of correct registration: Test 5 multiplayer worked (so SW didn't break the WS path) and the build artifacts confirm sw.js is generated by vite-plugin-pwa. Direct verification deferred to post-Caddy deployment."
why_human: SW activation is observable only at runtime in a browser; manifest installability warnings are surfaced by Chromium DevTools at runtime, not by static analysis.

### 4. Offline reload renders SPA shell

### 5. WebSocket multiplayer still works with SW active
expected: Open two browser tabs (any combination of Chromium browsers). In tab 1, create a game. In tab 2, join with a different player_id. Mark a square in tab 2 → tab 1 sees the mark in real-time. DevTools → Network → WS shows the connection open and frames flowing.
result: pass
notes: "Confirmed working in Firefox (no Chromium dependency for this test). Two-tab session: created game in tab 1, joined as second player in tab 2, marked a square in tab 2, change visible in tab 1 in real time. T-03-02-01 mitigation (no /ws urlPattern in runtimeCaching) is therefore confirmed end-to-end. This was the highest-stakes test in the suite — silent breakage of WS sync would have made multiplayer unplayable for Mum and Gordie."
