## Directory Purposes

**`backend/`:**
- Purpose: FastAPI server, business logic, database schema
- Contains: Python modules for routing, services, models
- Key files: `main.py` (entry point), `models.py` (contracts), `database.py` (schema)

**`backend/routers/`:**
- Purpose: REST and WebSocket endpoint handlers
- Contains: games.py, moments.py, cards.py, websocket.py, youtube.py
- Pattern: Each module defines FastAPI APIRouter with prefix and tags

**`backend/services/`:**
- Purpose: Core game logic and external integrations
- Contains: Game management, moment generation, card building, bingo detection
- Pattern: Async functions taking game_id/player_id, returning dict | None

**`frontend/`:**
- Purpose: React SPA build configuration and source
- Contains: TypeScript source, styles, public assets
- Key files: `vite.config.ts` (build config), `src/main.tsx` (entry point)

**`frontend/src/pages/`:**
- Purpose: Page-level components for each app state
- Contains: Home.tsx, CreateGame.tsx, Lobby.tsx, GameBoard.tsx, Help.tsx
- Pattern: One component per major view, receives handlers as props

**`frontend/src/hooks/`:**
- Purpose: Reusable stateful logic
- Contains: useWebSocket.ts for WebSocket lifecycle management
- Pattern: Custom hooks exported for use in pages

**`frontend/src/types/`:**
- Purpose: TypeScript type definitions
- Contains: game.ts with Game, Player, Card, Moment, etc. interfaces
- Pattern: Pure type exports matching backend Pydantic models

**`frontend/src/styles/`:**
- Purpose: Component styling (CSS modules or plain CSS)
- Contains: global.css (app-wide), bingo-card.css (grid styling)
- Pattern: Plain CSS (no CSS-in-JS)

**`frontend/dist/`:**
- Purpose: Built SPA artifacts (generated)
- Contains: index.html, assets/
- Generated by: `vite build` during production build
- Not committed: Listed in .gitignore

**`.planning/codebase/`:**
- Purpose: Architecture and structure documentation
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md
- Not generated: Hand-written by developers/agents

**`venv/`:**
- Purpose: Python virtual environment
- Not committed: Listed in .gitignore
- Activated by: `source venv/bin/activate` in run.sh

## Key File Locations

**Entry Points:**

- `run.sh`: Development startup (orchestrates venv setup, backend startup, frontend dev server)
- `backend/main.py`: FastAPI app with router mounting and SPA fallback
- `frontend/src/main.tsx`: React root mount
- `frontend/src/App.tsx`: Main routing and page logic
- `Dockerfile`: Container entry (runs `run.sh`)

**Configuration:**

- `backend/config.py`: Settings (database_path, anthropic_api_key, etc.)
- `frontend/vite.config.ts`: Dev server proxy to `/api` and `/ws`
- `frontend/tsconfig.json`: TypeScript compiler options
- `requirements.txt`: Python dependencies (FastAPI, aiosqlite, anthropic, etc.)
- `frontend/package.json`: NPM dependencies (react, vite, typescript, etc.)

**Core Logic:**

- `backend/models.py`: Pydantic validation schemas
- `backend/database.py`: SQLite schema and async connection management
- `backend/services/game_service.py`: Game CRUD operations
- `backend/services/moment_generator.py`: Claude API integration for content generation
- `backend/services/card_builder.py`: 5x5 grid generation with distribution logic
- `backend/services/bingo_checker.py`: Win detection (rows, columns, diagonals)
- `frontend/src/api.ts`: Centralized fetch wrapper for all backend calls

**Testing:**

- `backend/` has no tests (none found)
- `frontend/` has no tests (none found)

## Naming Conventions

**Files:**

- Backend Python: `snake_case.py` (game_service.py, moment_generator.py)
- Frontend TypeScript: `PascalCase.tsx` for components (Home.tsx, GameBoard.tsx), `camelCase.ts` for utilities (api.ts, useWebSocket.ts)
- Tests: Not found in codebase

**Directories:**

- Backend: lowercase plural (routers/, services/)
- Frontend: lowercase singular (pages/, hooks/, types/, styles/)

**Functions:**

- Backend: `snake_case` (async def create_game, async def list_games)
- Frontend: `camelCase` (const handleStart, const useWebSocket)

**Types/Interfaces:**

- Backend Pydantic models: `PascalCase` (GameCreate, PlayerJoin, CardSquare)
- Frontend TypeScript: `PascalCase` (Game, Player, Card, WSMessage)
- Backend enums: `snake_case` values ("tv_show", "youtube", "active", "lobby")

**Database Tables:**

- Lowercase plural (games, moments, players, card_squares)
- Columns: snake_case (source_type, source_name, winner_player_id, created_at)

**API Routes:**

- RESTful pattern: `/api/games`, `/api/games/{game_id}`, `/api/games/{game_id}/join`
- WebSocket: `/ws/{game_id}/{player_id}`

## Where to Add New Code

**New Feature:**

1. **Backend feature (e.g., new game mechanic):**
   - Add endpoint to `backend/routers/` with appropriate prefix
   - Implement logic in `backend/services/` with async functions
   - Add Pydantic model in `backend/models.py` if new request type
   - Update database schema in `backend/database.py` if new tables needed

2. **Frontend feature (e.g., new page):**
   - Create component in `frontend/src/pages/{FeatureName}.tsx`
   - Add type definition to `frontend/src/types/game.ts` if new data structure
   - Add API call to `frontend/src/api.ts` if new backend endpoint
   - Import page in `frontend/src/App.tsx` and add route case
   - Add CSS to `frontend/src/styles/` as needed

**New Component/Module:**

- Reusable component: `frontend/src/components/` (directory does not exist yet; create if needed)
- Utility function: `frontend/src/utils/` (directory does not exist yet; create if needed)
- Service module: `backend/services/{new_service}.py` with async functions
- Router module: `backend/routers/{new_router}.py` with APIRouter and endpoints

**Utilities:**

- Shared fetch wrapper: Already in `frontend/src/api.ts`
- Shared constants: Could add `frontend/src/constants.ts` (none currently exist)
- Backend helpers: Add to `backend/services/` as separate module
